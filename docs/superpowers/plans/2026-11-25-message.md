# 消息模块（conversations / messages）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 docs/05 §5.6 消息模块——会话（列表/发起/防重复）+ 消息（列表/发送）+ 已读（游标模型），把 v0.1 领养闭环真正闭环。

**Architecture:** 新增顶层模块 `com.pethelp.message`（controller/service(+impl)/dto/entity/mapper），沿用现有 MyBatis + Spring Security（`@AuthenticationPrincipal CurrentUser`）约定。已读用 `conversation_participants.last_read_message_id` 读游标实现 O(1) 标记；消息列表用 `id` 游标分页；会话固定 1:1、强制关联帖子、发起需至少一方是帖子发布者。

**Tech Stack:** Java 17, Spring Boot, MyBatis, PostgreSQL/PostGIS, Testcontainers (PostGIS + Redis), MockMvc, JUnit 5 + Mockito。

**Spec:** `docs/superpowers/specs/2026-11-25-message-design.md`

## Global Constraints

- 统一前缀 `/api/v1`；返回 `ApiResponse{code,message,data}`；错误码 `40000/40100/40300/40400/40900/42900/50000`，HTTP 状态 = `code/100`。
- 业务规则全在后端；客户端只传操作意图，**绝不传业务状态**。
- 所有写操作在 Service 层显式校验归属/参与者，越权 `403`；**禁止用 `assert` 做权限检查**。
- DTO 用 record；实体与 mapper 结果用可变 POJO（getter/setter）；`OffsetDateTime` 表示时间。
- 集成测试用真实 PostGIS 镜像（Testcontainers），**不用 H2**；单元测试与模块同包、Mockito mock mapper。
- 跨模块只依赖接口：`message` → `post`（`PostMapper`）+ `user`（`UserMapper`）。
- 无新增 Maven 依赖；本迭代唯一 schema 变更是 V4 迁移。

## Review Focus

| # | 输入/失败模式 | 期望行为 | 归属任务 |
|---|---|---|---|
| R1 | 非参与者访问某会话的消息/发送/已读 | 403 `无权访问该会话` | Task 1、4 |
| R2 | 双方都不是帖子发布者时发起会话 | 403 `至少一方须为帖子发布者` | Task 3 |
| R3 | 帖子 `COMPLETED`/`close` 后发送消息 | 正常 200（收发不受帖子状态影响） | Task 1 |
| R4 | 重复标记已读 | no-op，游标不变，不报错、不重复写 | Task 4 |
| R5 | 用户标记自己发送的消息为已读 | 403 `仅接收者可标记已读` | Task 4 |
| R6 | 分页期间有新消息插入 | 游标分页不丢不重（`before_id`/`after_id` 按 `id` 切片） | Task 1 |

游标分页 SQL（本任务只实现 findLatest/findBefore/findAfter 三个，均按 `conversation_id` 过滤、最终升序返回）：
```sql
-- findLatest: 最新 N 条（DESC 取 N 再反转）
SELECT id, conversation_id, sender_id, content, created_at
FROM messages WHERE conversation_id = #{conversationId}
ORDER BY id DESC LIMIT #{limit};
-- findBefore: 更旧（上翻）
... WHERE conversation_id = #{conversationId} AND id < #{beforeId} ORDER BY id DESC LIMIT #{limit};
-- findAfter: 更新（未读窗口）
... WHERE conversation_id = #{conversationId} AND id > #{afterId} ORDER BY id ASC LIMIT #{limit};
```

Service 逻辑（`listMessages`）：`conversationMapper.findById` 为 null → `NotFoundException("会话不存在")`；`participantMapper.exists(...) == 0` → `ForbiddenException("无权访问该会话")`；`afterId != null` → findAfter、`beforeId != null` → findBefore、否则 findLatest；limit 默认 10；结果按 `id ASC` 排序后映射为 `MessageResponse`。

`sendMessage`：同样存在性(404)+参与者(403)校验；`content == null || content.isBlank()` → `BadRequestException("消息内容不能为空")`；`content.length() > 2000` → `BadRequestException("消息内容过长")`；插入 `Message(conversationId, senderId=currentUserId, content)` 后返回 `MessageResponse`。

Controller：`@RestController @RequestMapping("/api/v1")`，`GET /conversations/{id}/messages`（query：`before_id`/`after_id` 可选、`limit` 默认 10）与 `POST /conversations/{id}/messages`，均经 `@AuthenticationPrincipal CurrentUser currentUser` 取 `currentUser.id()`。

- [ ] **Step 3: 实现 create 逻辑**

`createConversation(currentUserId, request)`（`@Transactional`）：
1. `postMapper.findById(postId)` null → `NotFoundException("帖子不存在")`。
2. `userMapper.findById(peerUserId)` null → `NotFoundException("用户不存在")`。
3. `peerUserId.equals(currentUserId)` → `BadRequestException("不能给自己发消息")`。
4. `!currentUserId.equals(post.getPublisherId()) && !peerUserId.equals(post.getPublisherId())` → `ForbiddenException("至少一方须为帖子发布者")`。
5. `existingId = conversationMapper.findExistingIdByPostAndPair(postId, currentUserId, peerUserId)`；非 null → 返回 `buildSummary(existingId, currentUserId)`。
6. 否则 `insert conversations(post_id)`（`useGeneratedKeys` 回填 id）+ 两条 `conversation_participants(conversation_id, user_id)` → 返回 `buildSummary(newId, currentUserId)`。

`findExistingIdByPostAndPair` SQL：
```sql
SELECT c.id FROM conversations c
JOIN conversation_participants p1 ON p1.conversation_id = c.id AND p1.user_id = #{me}
JOIN conversation_participants p2 ON p2.conversation_id = c.id AND p2.user_id = #{peer}
WHERE c.post_id = #{postId} LIMIT 1;
```

- [ ] **Step 3: 实现 read 逻辑 + mapper**

Mapper SQL：
```sql
-- markAllRead：游标推到该会话最大消息 id（单行）
UPDATE conversation_participants
SET last_read_message_id = (SELECT MAX(id) FROM messages WHERE conversation_id = #{conversationId})
WHERE conversation_id = #{conversationId} AND user_id = #{userId};

-- advanceLastRead：游标推到 ≥ 该消息 id（单行，幂等）
UPDATE conversation_participants
SET last_read_message_id = GREATEST(COALESCE(last_read_message_id, 0), #{messageId})
WHERE conversation_id = #{conversationId} AND user_id = #{userId};
```

`markConversationRead(currentUserId, conversationId)`：`conversationMapper.findById` null → 404 `会话不存在`；`participantMapper.exists(...) == 0` → 403 `无权访问该会话`；`participantMapper.markAllRead(...)`。
