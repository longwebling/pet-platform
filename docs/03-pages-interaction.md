# 03 — 页面结构与核心交互

> 第一版先完成 Web/H5 核心闭环。地图用高德，公开位置只渲染模糊坐标。

## 3.1 页面清单

| 页面 | 核心交互 | 权限 |
|---|---|---|
| 登录/注册 | 手机号 + 验证码 | 游客 |
| 首页 | 地图/列表切换、附近宠物筛选（物种、来源、距离） | 全部 |
| 发布宠物档案 | 表单 + 图片上传（健康/免疫证明）+ 地图选点 + 来源声明 | 普通用户 |
| 发布信息（寻主/领养/照护） | 选择已有关联档案或新建、照护填起止时间 | 普通用户 |
| 帖子详情 | 宠物信息、模糊位置地图、申请入口、联系发布人、发布人主页 | 全部 |
| 申请弹窗 | 留言 + 提交（领养/照护） | 普通用户 |
| 我的发布/档案 | 列表 + 状态筛选 + 编辑/下架 | 自己 |
| 我的申请 | 列表 + 状态筛选 + 撤回 | 自己 |
| 审核申请 | 通过/拒绝、查看申请人资料 | 发布者 |
| 交接确认 | 交接/归还确认按钮、位置授权、争议入口 | 安排双方 |
| 会话消息 | 会话列表、消息收发、交接信息分享 | 参与双方 |
| 举报 | 举报帖子/用户 | 登录用户 |
| 运营后台 | 内容审核、举报处理、下架、封禁、精确位置特殊授权 | 运营/管理员 |

## 3.2 核心交互细节

- **地图搜索**：高德 + PostGIS `ST_DWithin`，返回模糊坐标（geohash 截断到小区级 ~200m~1km）。
- **位置隐私分层**：
  - 公开地图/详情：仅模糊位置（`geo_hash` + 模糊描述「xx 小区附近」）。
  - 精确位置：申请通过后仍需对方通过 `location_access_grants` **明确授权**才可见（授权有 `expires_at`/可撤销）；访问时写入 `address_visibility_logs` 审计。
  - 交接位置：双方在会话中约定，可单独记录到 `handover_records.location`。
- **申请 → 预留**：发布人点「通过」时后端**条件更新**帖子状态（CAS），成功才创建安排/工单，失败提示「该宠物已被预留」或「时段冲突」。
- **双确认**：交接/归还需双方各自确认，单方确认后状态停留在「待对方确认」。
- **延期**：照护工单内发起延期，后端重校验时段冲突，冲突返回可用时段建议。

## 3.3 状态与 UI 映射

| 对象 | 后端状态 | 前端展示 |
|---|---|---|
| 领养帖子 | `OPEN` | 「可申请」 |
| 领养帖子 | `RESERVED` | 「已被预留」 |
| 领养帖子 | `COMPLETED` | 「已完成」 |
| 领养申请 | `PENDING`/`APPROVED`/`REJECTED`/`WITHDRAWN` | 待审核/已通过/已拒绝/已撤回 |
| 照护工单 | `PENDING_HANDOVER` | 「待交接」 |
| 照护工单 | `IN_PROGRESS` | 「照护中」 |
| 照护工单 | `PENDING_RETURN`/`COMPLETED` | 「待归还确认」/「已完成」 |
| 安排/工单 | `CANCELLED`/`ABORTED` | 「已取消」/「已异常终止」 |

> 第一版无任何「待支付/退款/资金」页面或状态。
