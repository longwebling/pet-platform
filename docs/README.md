# 宠物互助平台 — 需求分析与技术设计

面向中国大陆用户的**免费宠物互助平台**，主要提供：

1. 无主宠物的信息发布、寻主和免费领养申请。
2. 宠物主人短期无法照顾宠物时，发布免费的临时照护需求。
3. 用户通过地图发现附近的宠物信息。
4. 用户联系发布人、提交申请、沟通并确认线下交接。
5. 平台提供基本信息审核、举报和运营管理能力。

> **第一版定位**：只负责信息服务和双方沟通，**不参与任何资金流转**。

## 技术方向

- Java 17+ / Spring Boot（模块化单体起步）
- PostgreSQL + PostGIS（空间数据、时间冲突约束、范围类型）
- Redis（缓存、验证码限流）
- Vue 3 + TypeScript + uni-app（多端）
- 高德地图（定位、地理编码、地图渲染）

## 已确认决策（最新）

| 决策项 | 结论 |
|---|---|
| 商业模式 | **完全免费互助**，第一版不参与资金流转 |
| 领养费用 | **免费**，无任何费用/押金/保证金 |
| 照护费用 | **免费互助**，无照护费/押金/退款/结算 |
| 用户认证 | 手机号 + 基础用户资料（认证信息字段预留，暂不接第三方实名/信用） |
| MVP 优先 | **Web/H5**；MVP 总体含领养+照护，**首发 v0.1 优先领养闭环**，v0.2 再上照护 |
| 业务对象模型 | 区分「宠物档案 / 发布信息 / 申请 / 安排（工单）」；**发布者 ≠ 所有者**，含 `owner_id`/`authorization_status` 与授权关系表 |

## 待确认清单

| 编号 | 待确认项 | 当前默认 | 影响范围 |
|---|---|---|---|
| Q1 | 所有权核实机制 | 由发布人自证 + 平台人工核实（审核队列），无 AI 自动审核 | 状态机、运营后台 |
| Q2 | 寻主信息转为领养信息的规则 | 允许在核实后由发布人将「寻主」转为「领养」，需记录转换 | 帖子状态机、发布流程 |
| Q3 | 实名/信用认证 | 第一版仅手机号，`users` 预留 `verification` 字段 | user 表 |
| Q4 | 交接位置授权细节 | 申请通过≠自动获得精确住址；精确位置需对方明确授权，运营默认不可见 | 位置隐私、审计 |
| Q5 | 走失/受伤责任 | 平台仅提供信息服务，线下交接风险由双方自行承担，平台提供举报/仲裁入口，具体法律责任**待法务核实** | 状态机、免责声明 |
| Q6 | 内容审核方式 | 第一版人工审核（图片/文本），不做 AI 自动审核 | 审核流程 |

> 任何一条变更，对应章节需返工。涉及法律与业务规则的（Q1、Q5）**标记为待核实**，不擅自假设。

## 关键风险提示

1. **所有权与处置权风险**：发现流浪动物 ≠ 自动拥有领养处置权；疑似走失宠物须优先走寻主流程。未核实不得直接进入可领养状态。平台对「谁有权处置宠物」不擅自认定，需发布人自证并由平台审核，**法律责任边界待法务核实**。
2. **线下交接风险**：平台不参与资金与物权转移，交接过程中的走失、受伤、纠纷需在 `handover_records` 中留痕，作为举报/仲裁依据。
3. **位置隐私**：精确住址绝不公开；公开地图只返回模糊位置；精确位置访问需授权 + 审计。

## 远期规划（明确不进入第一版架构与 MVP）

- 付费领养、付费照护、资金托管、押金、退款、平台抽佣等交易能力——**如未来需要，需另行立项重新设计**，本套文档不包含其架构、表结构、状态机或 API。

## 全局约定（与 AGENTS.md 一致）

- 业务规则全部在后端实现，前端不得自行推进状态转移。
- 精确住址绝不公开，后端强制归属校验，所有状态转移服务端校验。
- 客户端不得直接传入并修改任意业务状态。
- 密钥、Token、密码不得写入仓库。
