# 07 — MVP 范围与迭代计划

> 第一版先完成 **Web/H5 核心闭环**，再考虑微信小程序与 App。不因最终多端而在第一版同时开发三套客户端。

## 7.1 MVP 总体范围 vs 首个上线版本

**MVP 总体范围**包含两大业务（均免费）：

1. 免费领养（寻主 / 救助 / 无主宠物信息发布 → 核实 → 免费领养申请 → 线下交接）。
2. 免费临时照护（主人发布照护需求 → 申请 → 线下交接 → 照护 → 归还确认）。

**首个上线版本（v0.1）**：优先完成**免费领养闭环**。

**后续小版本（v0.2）**：再上线**免费临时照护**。

### MVP 总体功能（14 项）

1. 用户注册登录（手机号验证码）。
2. 用户资料。
3. 宠物档案发布（含来源/所有权/授权声明）。
4. 寻主信息发布。
5. 免费领养信息发布。
6. 免费临时照护信息发布。
7. 地图附近宠物查询（模糊位置）。
8. 领养申请与审核。
9. 临时照护申请与审核。
10. 线下交接确认。
11. 临时照护归还确认。
12. 基础站内消息 / 联系功能。
13. 举报和下架。
14. 基础运营管理。

### 暂不实现（明确排除）

- 所有在线支付、资金托管、押金、保证金、退款、平台抽佣。
- 信用分、复杂推荐算法、AI 自动审核、复杂实时聊天系统。
- 微服务、复杂 MQ 架构。
- 微信小程序、Android/iOS App（第一版之后再做）。

## 7.2 发布节奏

| 版本 | 内容 | 目标 |
|---|---|---|

## 7.3 验收标准（v0.1 领养闭环）

- 领养全流程可走通：发布 → 核实 → 开放申请 → 申请 → 审核（同事务批量拒绝其余）→ 安排 → 交接 → 双方确认完成 → 宠物档案所有权/照护者/所有权状态更新。
- 并发下同一宠物不会被两个申请同时预留成功。
- 完成一次领养后，宠物档案归档且不阻塞未来再次领养（唯一索引仅约束 `PENDING_HANDOVER`）。
- 精确位置仅 `location_access_grants` 授权方可见，且有审计日志。
- 越权操作全部被后端拒绝（IDOR 测试通过）。
- 全程无任何资金/支付状态与页面。

## 7.4 远期规划（明确不进入第一版架构与 MVP）

付费领养、付费照护、资金托管、押金、退款、平台抽佣等交易能力——如未来需要，需另行立项重新设计，本套文档不包含其架构、表结构、状态机或 API。
