# 01 — 完整 PRD

## 1.1 产品定位

面向中国大陆用户的**免费宠物互助平台**。第一版只负责**信息服务 + 双方沟通 + 线下交接留痕**，**不参与任何资金流转**。

- 业务 A：免费领养（寻主 / 救助 / 无主宠物信息发布 → 核实 → 免费领养申请 → 线下交接）。
- 业务 B：免费临时照护（主人发布照护需求 → 申请 → 线下交接 → 照护 → 归还确认）。

## 1.2 目标用户

- **信息发布者（publisher）**：发布寻主/救助/领养信息的人，或发布照护需求的人。**不一定是宠物所有者**。
- **领养人（adopter）**：提交领养申请的用户。
- **照护人（caregiver）**：提交照护申请、实际照护宠物的用户。
- **宠物主人（owner）**：发布临时照护需求的宠物所有者。

## 1.3 核心价值

- 让流浪/无主宠物被看到、找到主人或找到新家。
- 让主人短期离开时宠物有人照护。
- 通过信息核实、申请审核、交接留痕和举报机制建立社区信任。

## 1.4 功能需求

### A. 用户侧

- 手机号验证码注册/登录。
- 用户资料（昵称、头像、简介）。
- 认证信息（字段预留，第一版仅手机号）。

### B. 宠物档案

- 发布宠物档案（物种、品种、年龄、性别、绝育、疫苗、健康描述、图片、位置）。
- 明确**信息来源**（`source_type`）：OWNED 自己饲养 / RESCUED 救助 / FOUND 疑似走失 / STRAY 确认无主。
- 明确**所有权状态**（`ownership_status`）：OWNED 有主 / UNKNOWN 待核实 / UNOWNED 确认无主 / TRANSFERRING 领养交接中。
- 明确**当前实际照护者**（`current_custodian_id`）。

### C. 发布信息（与宠物档案分离）

- 寻主信息（FINDING）：疑似走失宠物，优先寻主。
- 免费领养信息（ADOPTION）：核实后开放领养申请。
- 免费临时照护信息（FOSTER）：主人发布照护需求（含起止时间、照护类型）。
- 一个宠物可先后发布多种信息（如先寻主，未果后转领养）。

### D. 免费领养业务

- 发布寻主/救助信息 → 核实 → 确认领养条件 → 开放免费领养申请。
- 用户提交领养申请（多人可同时提交，同一宠物最终只有一个有效领养安排）。
- 发布人审核申请，通过后产生**领养安排**（不是领养完成）。
- 双方沟通、线下交接，双方确认后领养完成。

### E. 免费临时照护业务

- 主人发布照护需求（起止时间、类型：上门/寄养/遛狗/陪伴）。
- 照护人提交申请，主人审核。
- 确认照护安排 → 线下交接 → 照护开始/结束 → 双方确认归还。

### F. 通用

- 地图（高德）定位、位置模糊化、距离搜索。
- 站内会话消息（联系发布人、协商交接）。
- 交接记录、举报与审核、运营下架/封禁。

## 1.5 非功能需求

- **并发安全**：同一宠物只能有一个有效领养安排；同一宠物不能有重叠的照护时段。
- **安全**：资源级权限隔离、位置分级可见、防越权（IDOR）、审计日志。
- **可扩展**：多端共享同一套 REST API。
- **合规**：宠物信息需健康/免疫信息，图片/文本人工审核。

## 1.6 关键指标（MVP）

发布量、寻主成功率、领养申请通过率、交接完成率、照护履约率、争议率。

# 用户角色与权限矩阵

## 角色定义

| 角色 | 说明 | 关键权限 |
|---|---|---|
| 游客 | 未登录 | 浏览公开列表、查看模糊位置 |
| 普通用户 | 手机号登录 | 发布宠物/信息、申请、沟通、评价/举报 |
| 信息发布者 | 拥有某宠物档案或帖子的用户 | 编辑/下架自己的档案与帖子、审核自己的申请 |
| 申请人/领养人/照护人 | 对帖子发起申请的用户 | 撤回申请、确认交接/归还 |
| 宠物主人 | 发布照护需求的用户 | 审核照护申请、确认归还 |
| 运营 | 平台客服/审核 | 内容审核、举报处理、仲裁、内容下架、封禁 |
| 管理员 | 超级权限 | 用户封禁、帖子强制下架、数据导出、精确位置特殊授权审计 |

## 资源归属规则（贯穿全站）

- 宠物档案（`pets`）→ 三方语义分离：信息发布者 `publisher_id`、当前所有者 `owner_id`（可空）、实际照护者 `current_custodian_id`；另有 `ownership_status` 与 `authorization_status`。
- 发布信息（`pet_posts`）→ 归属发布者 `publisher_id`。
- 领养申请（`adoption_applications`）→ 归属申请人 `adopter_id`，审核权归帖子发布者。
- 照护申请（`foster_applications`）→ 归属照护人 `caregiver_id`，审核权归主人。
- 领养安排（`adoption_arrangements`）→ 双方：`adopter_id` 与 `custodian_id`（交接方）。
- 照护工单（`foster_orders`）→ 双方：`owner_id`（主人）与 `caregiver_id`（照护人）。

## 所有权与处置授权模型（P0-2）

**发现者/救助者 ≠ 所有者**，不能默认其拥有宠物处置权。谁有权做什么由以下规则界定：

| 操作 | 有权者 |
|---|---|
| 发布寻主信息 | 任何发现者/发布者 |
| 发布免费领养信息 | 所有者本人（`owner_id==publisher_id`）或持有 `pet_authorizations(PUBLISH)` 有效授权者 |
| 批准领养申请 | 帖子发布者 + 具备该宠物 `ADOPTION_APPROVAL` 授权（所有者本人默认具备） |
| 确认领养交接 | 安排双方，其中交接方为当前照护者（所有者或获 `CUSTODY` 授权者） |
| 发布/审核照护需求 | 第一版要求**所有者本人**（`publisher_id==owner_id`，后端校验），不支持代发照护 |

- 自己饲养（`source_type=OWNED`）：所有者本人发布，`authorization_status=SELF`。
- 救助流浪（`RESCUED`）：`owner_id` 可空，处置授权待平台核实（`PENDING`）。
- 发现疑似走失（`FOUND`）：`UNAUTHORIZED`，仅能寻主，不得直接领养。
- 医院/照护者代发：需 `pet_authorizations` 授权记录（`AUTHORIZED`）。

> **处置权 ≠ 所有权状态**：`ownership_status=UNOWNED`（确认无主）**不自动授予处置权**，仍须 `authorization_status` 核实为 `AUTHORIZED`（平台授予）后才有权发布领养。**发现疑似走失转领养须同时满足**：① `ownership_status` 已核实为 `UNOWNED`；② `authorization_status` 已核实为 `AUTHORIZED`；③ FINDING 帖子已过寻主公示期（运营确认）。任一不满足则拒绝转换，仍仅可寻主。

# 业务流程

## 业务 A：免费领养流程

```
发布人                          平台                          领养人
  │ 发布寻主/救助信息(来源、模糊位置) │                              │
  │──────────────────────────▶│ 内容审核(人工)                    │
  │ 必要信息核实                 │                              │
  │ 确认具备领养条件             │                              │
  │ 开放免费领养申请(转领养帖子)   │                              │
  │                           │◀──────── 浏览/提交申请(留言) ───────│
  │ 审核申请(可多个申请)         │                              │
  │ (通过→产生领养安排，宠物预留)  │                              │
  │                           │── 生成领养安排(待交接) ─────────▶│
  │                           │  双方可见交接信息(授权)           │
  │                           │── 线下交接 ────────────────────▶│
  │ 确认已交接                  │                              │ 确认已接收
  │                           │ 双方确认 → 领养完成               │
  │                           │ 更新宠物档案归属/所有权            │
```

### 重要规则

1. 信息发布者**不一定是宠物所有者**。
2. 发现流浪动物**不自动拥有领养处置权**。
3. 疑似走失宠物**优先走寻主流程**。
4. 未完成必要核实的宠物**不能直接进入可领养状态**。
5. 领养申请可由**多个用户**提交，但同一宠物最终只有**一个有效领养安排**。
6. 领养审核通过**不代表交接完成**。
7. 领养完成需记录交接情况，并由**双方确认**。
8. 第一版**不收取任何领养费用**。

## 业务 B：免费临时照护流程

```
主人                          平台                          照护人
  │ 发布照护需求(起止时间、类型、模糊位置) │                          │
  │──────────────────────────▶│ 内容审核                      │
  │ 审核照护申请                │                              │
  │ (通过→产生照护工单)         │                              │
  │                           │◀────────── 提交照护申请 ─────────│
  │ 确认照护安排                │                              │
  │                           │ 生成照护工单(待交接,时段锁定)     │
  │                           │── 线下交接 ───────────────────▶│
  │                           │ 照护开始(记录)                  │
  │                           │ 照护结束                        │
  │ 确认已归还                  │                              │ 确认已归还
  │                           │ 双方确认归还 → 照护完成          │
```

### 重要规则

1. 第一版临时照护**完全免费**。
2. 明确**宠物主人**与**实际照护人**的身份。
3. 照护工单需有明确的**开始时间和结束时间**。
4. 同一只宠物**不能同时存在时间重叠的有效照护工单**。
5. 照护开始和归还都**需要记录**（`handover_records`）。
6. 需要考虑**取消、延期、爽约和异常事件**。
7. **不涉及**照护费用、押金、退款和平台结算。
